ROTEM — an open CAN FD heading reference for FRC

It reports your heading, and it reports how much it trusts it.
Published protocol, MIT library, tooling that runs on Linux.

Status: hardware v1.0 rev B is a routed, ERC/DRC-clean first-article design. First boards are being built. The CAN protocol draft is public below. Nothing on this page is for sale yet, and no performance figure is claimed until we have measured it and published the method alongside it.

What it is

A 50 × 50 mm four-layer CAN FD module built around an ICM-45686 IMU and a fitted MMC5983MA magnetometer, with an STM32U575, protected 6–28 V input, onboard logging flash and a USB-C device port. It reports orientation to robot code over the FRC CAN bus, and it reports how much it trusts that orientation.

What is different about it

  • It tells you when it is wrong. Yaw uncertainty from the filter covariance, live bias estimate, vibration level and clipping counters, magnetic-disturbance state and calibration age are first-class signals on the bus — surfaced through the WPILib Alert API, not buried in a debug build.
  • Per-unit factory calibration. Gyro scale factor, cross-axis misalignment and temperature-dependent bias, written to device flash and shipped with a serial-numbered certificate. Scale-factor error is what produces degrees of drift per rotation, and it cannot be fixed in robot code.
  • Onboard black-box recorder. Full state logged to onboard flash independent of robot code and independent of the bus, downloaded over USB-C as a native WPILog that opens directly in AdvantageScope. No vendor tool, no format conversion.
  • Tooling that runs anywhere. A browser configurator over Web Serial, plus a native desktop app for Windows, macOS and Linux, plus a CLI. It works on a bench with only USB power — no roboRIO, no deployed code, no bus.
  • Open and unlicensed. The full CAN specification is published, the libraries are MIT, and no feature — including synchronised sampling — costs money or requires companion hardware.

One library, every device

ROTEM is the first of several SAPPHIFY devices, and they all share one FIRST manufacturer ID, one published protocol, one vendor library, one configuration tool and one log format. Where it is going

ROTEM targets the 2027 control system: CAN FD and multiple buses on Systemcore, with classic CAN 2.0B retained for roboRIO teams. Java, C++ and Python at parity, with drop-in wrappers so migration is one line, plus YAGSL and AdvantageKit integrations.

Before release we will publish an open test harness and raw datasets comparing ROTEM against the existing FRC options on the same chassis — rotation-count error, match-duration drift, vibration response, collision recovery. Reproducible by any team. That is the only kind of performance claim worth making.
